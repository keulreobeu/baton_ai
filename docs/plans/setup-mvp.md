1. 코디네이터가 base, 현재 Task·lease, 기존 설치·스킬·Orca·프로젝트 설정 경계를 확인한다. 승인 범위는 사용자 최종안의 환경 조사·구성 지침 및 오프라인 구현이다.
2. 작성자 한 명이 루트 SETUP과 독립 정책표에 기존 스크립트·정본과 선택 의미를 연결한다. 설정 스키마·오케스트레이터·검사 엔진은 추가하지 않는다. 같은 상대 구조로 wheel에 싣고 기존 배포 확인 스크립트에서 설치 파일 내용과 링크를 검사한다.
3. 작성 중에는 문서 진입·프리셋·Checker 표, 설치기 유지/충돌, INPUT_CHECK 미실행 및 상태를 확인한다. checkpoint에서는 영향 모듈 전체, 고정 base SDD와 scratch wheel을 확인한다. 사용자 변경·실행 불가 및 중단 재개는 문서·기존 동작 사례를 구분해 기록한다.
4. 최종 후보는 BATON 자체 공식 순차 V3를 1회 수행하고 별도 작성 실행과 분리한 독립 검토를 받는다. 필수 원격 CI와 실제 호스트 확인 결과는 별도로 귀속한다. 실제 설치·권한·인증·모델 실행, 외부 게시·병합은 각각 원래 승인 조건을 유지한다.
