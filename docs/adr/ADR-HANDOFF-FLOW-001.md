### 로컬 결정과 향후 연결

공통 Markdown에 용도별 본문 하나와 필요한 모듈만 넣는다. BATON Task·승인은 BATON, 실행·생존·workspace 배정은 Orca, 소스와 ref는 Git, 제품 판정은 기존 증거 계약에서 읽는다. Chat의 사용자 결정은 정확한 근거로 연결하고 Dot은 읽기 전용 브리핑에 사용한다. 인계 산출물은 다음 행동을 설명한다. 수신자는 그 행동의 현재 권한과 실제 상태를 원천에서 확인한다.

|단위|제안하는 입력/출력 계약|
|---|---|
|작성 입력|Task 또는 관리 범위, 유형, 책임 관계·송수신 역할, 시각과 UTC offset, 소유자가 제공한 관측과 근거, 작성자의 의미 변경분. 기존 Task/Spec/코드·승인 근거로 유효성을 확인할 수 있는 의미 단위만 재사용한다|
|근거 결속|상태·검증 주장의 출처와 관측 시각, 관련된 경우에 한해 revision·대상 base/candidate·범위·실행 식별자. 유효한 원래 근거가 없으면 UNKNOWN. 이미 수행한 검사라도 다른 대상이면 STALE|
|작성 출력|완성된 UTF-8 Markdown 하나. 별도 기존 전달 영수증에 버전·문서 해시·작성 검사 대상·시각·결과·미확인 사항을 기록한다. 해시는 최종 바이트에서 계산한다. 문서 안에 자신의 해시를 넣지 않는다|
|인수 출력|수신자의 현재 관측, 재사용한 정적 검사 범위, 다시 확인한 승인·SHA·소유권·WIP, 다음 행동의 가능/차단 이유. 정보 제공 DELIVER는 writer 권한이 없어도 읽을 수 있다. 책임 이전 TRANSFER에는 새 writer 증명이 필요하다|

두 입력이 같은 SHA라도 Task, 승인, 검증 범위나 미게시 파일 내용은 다를 수 있다. 변경된 단위와 그것에 의존하는 요약만 다시 작성하고, 유효한 내용을 최종 카드에 펼쳐 넣는다. 제품 증거를 재사용하려면 제품의 기존 조건을 만족해야 한다.

### 실패와 부작용

Task/관리 범위·소유 writer 기준으로 저장 대상을 격리한다. 권한 있는 한 writer가 기존 이벤트 ID/순번과 현재 산출물을 대조하고 임시 파일에 작성·검사한 다음 원자적으로 교체한다. 자동과 수동 요청의 동등성은 수신 대상, 원래 체크포인트/이벤트, 내용에 결속한다. 단순 도착 시각은 순서의 증명이 아니다. 같은 대상의 stale·충돌 입력에서 이전 정상 산출물을 지킨다. 정착과 전달 결과를 모르면 재전달 전에 기존 영수증을 읽는다. 단계별 오류·시각을 요약하고 원장/로그의 원문은 전송하지 않는다.

이 설계는 별도 Core·상태 머신·DB·정책 엔진·오케스트레이터·adapter 프레임워크나 인계 검증 Agent를 요구하지 않는다. 중앙 HANDOFF 문서에 동시 쓰는 방식은 writer 격리를 보장하지 못한다. 매번 전체 문서를 모델로 재작성하면 유효한 결정이 유실되거나 비용이 늘 수 있다. Provider 종료 Hook만 쓰면 비정상 종료 또는 미지원 호스트의 체크포인트를 놓친다. 기존 Markdown 진입점과 HANDOFF-001을 유지하고 안정성이 확인된 이벤트부터 연결한다.

### Eng Review Amendments

후보 `6db1e98`의 내부 FAIL 후 정착 자료의 시점을 구체화했다. 예약은 ingest 중 해제되므로 직전의 읽기 전용 관측과 반환 직후의 동일 Task 정착 이벤트를 대조한다. 리뷰어 HEAD와 판정의 출처는 해당 리뷰 dispatch다. 마스터 배정 `msg_7a1232574382`에 따라 카드별 최소 영수증을 문서와 별도로 보관한다. 재시도는 최초 영수증·현재 출처·최종 문서 digest를 모두 확인한다. 각 경계 사례와 회귀는 Task의 두 번째 독립 검토 표에 있다.

독립 검토에서 확인한 권한·근거 결속 오류를 반영한다. 승인과 소유권은 수신자·행위·현재 근거에, 이동 증거는 동일한 manifest·ref·복원 Task에 묶는다. 이전 문서에서 의미 필드를 가져올 때는 현재 필드 기준과 당시 결정 revision을 확인한다. 최종 파일만 영수증으로 열 수 있으며 미완성 파일은 별도 작업 디렉터리에 둔다.

기존 관리 DB에 읽기 전용 연결을 열어 한 Task의 선택 열과 마지막 이벤트 순번을 대조한다. 정착 투영은 원래 ingest의 반환 뒤에 실행한다. 보존·읽기 실패 시 기존 정착 상태와 종료 코드를 그대로 반환하고 카드 결과만 차단으로 기록한다.

W1 소유자가 확인한 게시 계약에 따라 PORTABLE은 Git 전담 주체가 별도 권한으로 게시하고 원격 read-back한 결과를 소비한다. `local_saved`만으로 PC 이동을 안내하지 않는다. W4 검증·W2 ADAPT의 후속 변경은 승인된 인터페이스를 받은 뒤 비교한다.

Phase 2~3 보존은 같은 경로의 정상 문서를 교체하지 않고 이벤트별 완성된 카드를 한 번만 노출하는 방식으로 구체화했다. 같은 볼륨의 임시 파일에 쓰고 원자적 hard link 생성으로 슬롯을 선점한다. 수신자·유형을 슬롯에 포함해 동일 이벤트의 다른 정당한 전달 대상을 분리한다. 미지원 파일시스템과 다른 내용의 재요청은 차단한다. 정본의 이벤트 순번을 계속 사용하므로 W3는 최신 포인터나 별도 원장을 소유하지 않는다.
