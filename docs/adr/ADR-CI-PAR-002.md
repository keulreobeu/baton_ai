## 배경
- CI-PAR-001(ADR-CI-PAR-001, D19)은 테스트 실행 단계만 pytest-xdist 옵트인 backend로 바꿀 수 있게 했다. 기본값은 순차다.
- 단계는 G1(보조 도구) → G2(계약) → G3(비활성 공식 연결) → G3b(자격 상수만 켬) → G4(원격)다.
- G1은 4차 검토 PASS(finding 0)다. 최종 병합 쌍(CI-EVID `06a18e7`)에서 순차·xdist 954 PASS, FAIL 0, equivalent, uncertain 0이었다. 단, EVID-R4-01 수정 뒤 재검증이 필요하다.
- 현행 계약 세 곳이 공식 경로의 병렬 선택점을 막는다: 사다리 문단의 "공식 순차", CI-OPT-001 AC-13의 "순차 유지"·"공식 검증 병렬화 범위 밖", CI-VTIER-001:16의 "병렬 실행기는 만들지 않는다".

## 결정 (제안)
1. **한 번에 개정한다.** G2에서 문서와 고정 문구 테스트를 한 커밋으로 바꾼다. 문구는 G3b 뒤 상태까지 조건부로 적는다. 그래서 G3b는 CI-PAR-001 AC-08대로 상수만 바꾸는 1커밋으로 남는다.
2. **기본값과 자격을 분리해 적는다.** "공식 `verify_environment.py` 1회(기본 순차)"와 "G3b가 main에 반영되기 전 xdist 결과는 공식 증거 자격이 없다"를 따로 쓴다.
3. **금지는 지우지 않고 예외만 연다.** CI-OPT AC-13의 "공식 검증 병렬화 범위 밖"과 CI-VTIER:16의 "병렬 실행기 금지"는 남긴다. 외부 pytest-xdist 보조 backend의 조건부 연결만 명시 예외로 둔다. BATON 자체 병렬 실행기·스케줄러는 계속 만들지 않는다.
4. **계약 근거에 성능 수치를 쓰지 않는다.** 근거는 동등성 대조와 fail-closed 성질이다. 측정은 단일 PC 1회라 일반화하지 않는다.
5. **신뢰 경계를 문서에 남긴다(D29).** 로컬 PASS는 진행용이다. 원격 gate는 PR 내용으로 무력화될 수 있어 무결성을 보장한다고 쓰지 않는다.

## 대안과 기각 이유
- **A. 사다리 문구를 G3b까지 "공식 순차"로 두기:** G3 단계의 실제 상태(공식 진입점에 비활성 선택점 있음)와 맞지 않는다. G3b에서 문서도 고쳐야 해서 "상수만 바꾸는 1커밋" 원칙이 깨진다. 사용자 결정 후보 U1로 남긴다.
- **B. 금지 문구 삭제:** 자체 병렬 실행기·스케줄러 금지까지 사라진다. CI-VTIER의 단일 planner 원칙을 약하게 한다.
- **C. G3 단계별로 나눠 여러 번 개정:** 계약 문서 변경 횟수와 독립 검토 회차가 늘어난다. 각 단계 사이에 문서와 코드가 어긋나는 기간이 생긴다.
- **D. 제출본 rev5 문구 그대로:** "…통과할 때만 적격"이라고 적어 G3b 게이트가 문구에 드러나지 않는다. D30 경계(G3b 전 증거 자격 없음)를 명시하도록 고쳤다.

## 결과
- G2 개정 뒤에도 공식 증거는 순차 V3 결과뿐이다(G3b 전).
- P3·P3b 후보는 변경 전과 같은 공식 순차 V3·독립 검토·원격 CI로 검증한다(CI-VTIER-001:53).
- 남은 결정: T20 정책(G3 전), U1~U5(TASK-CI-PAR-002 "사용자 결정 후보").
