## GIT-R1-001-REQ-01 게시와 로컬 후보

### GIT-R1-001-AC-01

start, checkpoint, refresh 및 재개는 원격 ref를 쓰지 않는다. 미게시 후보의 base가 전진하면 소스·소유 ref·부모·tree를 대조하고 로컬 통합만 기록한다. 이전 후보에 묶인 검증과 승인은 새 후보에서 효력을 잃는다. 충돌, 변경된 source, 다른 writer의 tip은 보존한다.

### GIT-R1-001-AC-02

Task 게시와 HANDOFF orphan은 목적·저장소·대상 ref·내용·주체·기간·승인 revision이 일치하는 신뢰된 publisher에서만 허용한다. Task 게시에는 해당 후보 검토·검증, scope와 미게시 전체 이력 검사가 필요하다. 원자적 expected-old 갱신·read-back으로 중복 요청을 정산한다. 승인이나 증거가 빠졌을 때 원격 쓰기는 0이다.

## GIT-R1-001-REQ-02 등록과 독립 증거

### GIT-R1-001-AC-03

관리 등록한 같은 저장소 ID, Task, owner, head repo/ref/SHA, base와 PR 번호의 OPEN·ready PR만 판정한다. 기준 정책이 지정한 발행자·workflow·필수 검사 전체와 최신 시도, 검증 대상·통합 tree·민감 승인이 일치해야 한다. Draft, 참고용, 소유 불명, 실패·누락·stale 증거는 보류한다.

## GIT-R1-001-REQ-03 병합 관측·안정화·정리

### GIT-R1-001-AC-04

등록 PR의 실제 merge commit M을 조회해 도달성 및 순서 있는 부모 [B,H]와 tree T를 대조한다. GitHub 서버의 base 결속과 직렬화를 실측하기 전에는 무인 병합을 보류한다. caller의 receipt JSON만으로 Task를 완료할 수 없다.

### GIT-R1-001-AC-05

repo별 owner/epoch·intent와 M의 post-merge push CI 및 최신 main 성공을 확인한다. 실패·미확인은 다음 병합과 정리를 막는다. 소유자·현재 tip·보존 여부를 확인할 수 없는 ref는 보존한다. 실환경 전환은 01~07 전체 수락 후 별도 승인 대상이다.
