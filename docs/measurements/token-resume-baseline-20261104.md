기록일 2026-11-04 (KST). 측정 대상: BATON 복사·P0·SDD 도입 작업.
**실측**은 로컬 세션 로그(`~/.claude/projects/.../*.jsonl`, `~/.codex/sessions/**/*.jsonl`)와
앱의 사용량 표시에서 읽은 값이다. **추정**은 실측에서 계산한 값이고, 아직 실험으로 확인하지 않았다.

## 읽는 법

- 토큰 수와 한도 소모는 비례하지 않는다. 캐시 읽기는 싸고, 캐시 쓰기는 비싸며, 가중치는 공개되어 있지 않다. 그래서 토큰과 한도 %p를 함께 적는다.
- Claude와 Codex의 토큰·%는 서로 환산하지 않는다. 플랜과 모델이 다르다.
- 호출 비용은 대체로 그 시점의 컨텍스트 크기에 비례한다. 재개 방식의 차이는 대부분 여기서 나온다.

## 고정 기준선과 절감 추정

같은 작업을 두 번 하지 않고, 실제 호출 수는 그대로 둔 채 컨텍스트만 기준값으로 바꿔 계산한다.
결과는 측정값이 아니라 추정치로 표시한다. 기준값은 바꾸지 않는다.

```text
기존 방식 예상 = 실제 호출 수 × 기준 컨텍스트 + 재개 비용
절감률        = 1 − (실제 처리 토큰 ÷ 기존 방식 예상)
```

| 2026-11-04 기준값 | 값 |
|---|---:|
| Claude 큰 세션 컨텍스트 | 680,000 / 호출 |
| Claude 캐시 만료 재개 비용 | 605,077 (캐시 쓰기) |
| Claude 새 세션 참고값 | 170,000 / 호출 (추정) |
| Codex 큰 스레드 컨텍스트 | 330,000 / 호출 |

함께 볼 값: 실제 호출 수, 재작업 횟수, 닫힌 게이트 또는 검증 AC 1개당 토큰, 구독 한도 %p.
Claude와 Codex는 합치지 않는다. 한 건이 아니라 여러 건의 평균과 범위로 판단한다.

해석:
- 메인 호출 평균 컨텍스트는 약 74만이었다. 고정 기준 680,000과 비교하면 절감은 없고, 오히려 큰 세션 비용을 그대로 냈다. 13회 × 680,000 = 884만 예상에 실제 964만이다.
- 같은 13회를 새 세션 참고값으로 환산하면 약 221만이다. 새 세션이었다면 메인 처리량이 약 77% 적었을 것으로 추정한다. 다만 이 작업은 새 세션에서 실제로 측정하지 않았다.
- 한도 +11%p에는 메인과 독립 리뷰 3회가 함께 들어 있다. 리뷰는 컨텍스트가 작아(3.6만~5.5만) 토큰은 메인보다 훨씬 적었다.
- 재검토 3회 중 2회는 수정 시도 때문에 생겼다. 닫힌 게이트는 1개이고, 게이트당 비용은 위 합계 전체다.
- 인계 카드의 토큰 효과는 이 측정으로 알 수 없다. 세션 문맥이 이미 있었기 때문이다. 범위를 좁히는 효과만 관찰했다.
- 09:51 구간은 재작업 없이 끝났다. 고정 기준 예상 476만(7회 × 680,000)에 실제 544만이고, 새 세션 참고값 119만으로 환산하면 메인 처리량이 약 78% 적었을 것으로 추정한다. 이 환산도 측정값이 아니다.
- 두 구간 합산 한도는 호출 1회당 메인 기준 약 0.75%p다(하위 리뷰 포함, 20회에 +15%p). 재작업이 없어도 큰 세션의 호출 비용은 줄지 않는다.
