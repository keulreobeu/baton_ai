## 배경
2026-11-20 PoC(P0~P7)와 장기 재평가(LT rev2)에서 다섯 대안을 비교했다(REFERENCE_ONLY).
- A: 기존 유지
- B: Bazel 병렬만
- C: Bazel 실행+영향 분석
- D: Bazel 전체 교체
- E: 다른 오픈소스(pytest-xdist)

장기 재평가는 하이브리드 구조와, 사용자 기준인 구현량·병렬 성능도 함께 평가했다.

## 결정 (사용자 D19, 2026-11-20)
- **유지:** V1/V2/V3 정책·planner·증거·승인 게이트.
- **교체 지점:** 테스트 실행 단계 하나만 교체할 수 있게 한다. pytest-xdist 옵트인 백엔드를 두고, 기본값은 순차다.
- **증거 자격:** 계약 개정(G2)과 공식 연결(G3)이 main에 반영되고 같은 실행의 동등성 대조가 통과하기 전에는 xdist 결과를 공식 완료 증거로 쓰지 않는다.
- **단계:** G1 보조 도구·의미 검증 → G2 계약 → G3 공식 연결 → G4 원격(Spec 게이트 표).
- **보존:** Bazel 전면 교체와 캐시는 우선순위에서 제외하고, 실험은 후속 연구 자료로 보존한다.

## 근거 (실측·계산, LT rev2 §3·§11)
- **동등성:** xdist는 로컬·원격 Windows 3.11/3.12·Ubuntu에서 777 ID·결과가 순차와 같았다(43회).
- **병렬 성능(4 worker, 순차 대비, PoC 2단계 Trace2 켬, 순차는 Windows 1회·나머지 3회 중앙값):** 원격 Win3.12 883→443초, Win3.11 1196→545초, Ubuntu 87→30초다. 같은 조건 Bazel은 678/595/37초였다. Trace2 없는 1단계 단일 실행은 Win3.12 1108→433초, Win3.11 1054→460초다.
  - 로컬 12코어는 1024→230초(4.45×)다.
  - 원인은 분배 단위다. xdist는 테스트 ID 단위라 최장 ID 51.6초가 하한이다. Bazel은 모듈 단위라 최장 타깃 330.5초가 하한이다.
- **구현량:** xdist 실행 경로는 19줄이다. 동등성 검증 258줄은 Bazel도 똑같이 필요하다. Bazel은 설정·런처 101줄과 Windows 보정이 더 든다.
- **캐시:** `offline_suite` 재사용은 분리·기본 비활성이며 원격 CI에서는 쓰지 않는다. xdist와 함께 쓸 수 없다. Win3.12에서 Bazel이 이기는 데 필요한 s·h(0.35)가 관측 상한(0.113)보다 높다.
- **장기 이득:** 실제 V1/V2(262~322 tests, 378~419초) 반복에도 같은 백엔드를 쓸 수 있어 반복 이득이 누적된다[추정, AC-14에서 실측].

## 대안과 기각 이유
- **Bazel(B·C·D):** 공식 경로에 캐시 이득을 적용할 수 없고, 병렬은 xdist가 더 빠르며 구현량이 크다. 로컬 SAC에서는 정책상 실행하지 않는다(D5).
- **하이브리드:** 이 PC에서 Bazel 쪽을 실행할 곳이 없고, 엔진 2개를 운영하는 비용만 든다.
- **기존 fast runner 확장:** 자체 병렬 실행기는 구현하지 않는다는 원칙과 충돌하고, 이미 있는 오픈소스 기능을 다시 만드는 것이다.

## 결과
- 새 코드는 ID inventory·대조·결과 정규화·worker 예산과 실행 단계 백엔드 분기로 한정한다.
- 외부 의존은 직접 2개, 전이 포함 8개를 선택 extra로 둔다. 기본 설치는 표준 라이브러리만 쓴다.
- 철회: 설정을 끄면 현행 순차로 돌아간다. G2(P2) 이전에는 계약 문서 변경이 없고, G3 이전에는 공식 경로 코드 변경이 없다.
- 남는 위험: Spec RA-1~RA-5. 특히 RA-1(pytest의 unittest subTest 조기 중단 등)은 G1의 AC-15 의미 검증으로 판정 동등성을 확인한 뒤에만 G2로 간다.

## 재검토 조건
- **xdist 철회:** 동등성 불일치가 재현되거나, 병렬 간섭이 관측되거나, 의존성 공급망 문제가 생기면 A 단독으로 돌아간다.
- **Bazel 재검토:** LT rev2 §7 조건을 따른다.
  - 서명 배포 또는 승인된 실행 환경
  - Git 격리 뒤 Win3.12에서 s·h가 손익분기 이상
  - 캐시 무결성 검증 수단
  - 미선언 입력 완전성
  - 계약상 재사용 허용
  - cold≈0 환경
