## SETUP-001-REQ-01 AI가 최소 개입으로 선택한 환경을 구성한다

### SETUP-001-AC-01

최종안 AC-01~10, 18. AI가 checkout이나 배포 wheel의 SETUP.md에서 사용자 선택이 필요한 순서를 찾을 수 있다. 탐색, 공급자 선택(기존 선택 재사용), 필요한 설치·활성·권한의 묶음 승인, 승인 범위의 환경 구성과 인증 확인, 신규 프로젝트의 방식 선택 순이다. 기본 도구·Orca·스킬·네이티브 기능·Google 개인 사용자 Antigravity 경로를 적용한다. 거절·미지원은 해당 기능 제한으로 남긴다. 실제 지원과 설치·활성·사용을 구분한다.

## SETUP-001-REQ-02 독립 정책과 기존 계약을 운영한다

### SETUP-001-AC-02

최종안 AC-11, 15~17, 20. 다섯 프리셋의 실제 다섯 값과 상세 선택을 유지한다. SDD 정보·파일 형식, Review의 주체·작업 단위 완료 시점, Validation의 필수 시점, Checker의 도구, Roadmap의 성과 갱신이 서로 불필요한 의무를 만들지 않는다. 기존 승인 Full·CI·비재사용 조건이 우선이다. 필요 검토자/도구 부재와 바뀐 통합 후보를 성공 처리하지 않는다.

## SETUP-001-REQ-03 재실행·환경 이동·미확인을 보존한다

### SETUP-001-AC-03

최종안 AC-12~14, 19. 이전 요구 환경과 실제 로컬 관측을 구분하고 기존 사용자 선택·파일·의도적 off를 보존한다. 신규 Task가 정본을 읽는다. 중단·충돌은 해당 쓰기만 보류하고 기존 설정·원본 작업 기록을 재사용한다. 비밀·로그인·권한·절대경로를 다른 PC에 복제하지 않는다. Ready·Partial·Blocked를 확인한 범위에만 귀속한다.

대표 문서 회귀와 기존 설치기 양·음성 사례는 [Task](../tasks/TASK-SETUP-001.md)에서 추적한다. 이 검사는 실제 모델, 새 PC 복구, 호스트의 자율 해석·실행을 입증하지 않는다.
