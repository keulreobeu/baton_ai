내부 작업의 토큰 효율과 기존 시스템 호환성을 유지하면서 사용자 보고의 가독성을 높인다.
내부 명칭과 사용자 표시 명칭을 분리한다. 명칭 사전과 보고 규칙의 원본은 [docs/reporting.md](../reporting.md) 하나다.

## REPORT-001-REQ-01 표시 명칭 사전

사용자와의 대화·보고(백그라운드 알림·중간 보고 포함)는 한국어가 기본이고 사용자가 지정한 경우만 다른 언어를 쓴다(2026-11-18 사용자 지시 "사용자 보고 언어 정책").
사용자 보고에는 표시 명칭을 쓰고, 내부 식별자(코드·문서·파일명·Task ID·CLI·API·DB·JSON·로그·에이전트 간 인계)는 바꾸지 않는다.
사전은 검증 단계(V1~V3), 변경 위험 등급(L0~L3), 결함 심각도(P1~P3), 주요 기능, 작업 상태, 계약 문서 상태·검증 결과, 기타 식별자 표시 방법을 담는다.
사전에 없는 축약어는 원래 식별자를 유지한다. 표시는 계약·검증 강도·위험 등급·상태 판정·승인 조건을 바꾸지 않는다.

### REPORT-001-AC-01

`docs/reporting.md`는 한국어 기본 원칙(언어 절)을 담는다. 표에서 V1~V3, L0~L3, P1~P3가 빠짐없이 한 번씩 정의되고, `baton.managed.STATES`의 모든 작업 상태와
VERIFIED·NOT_RUN·PARTIAL에 표시 명칭이 있다. 표의 내부 키는 표마다 중복이 없고 표시 값이 비어 있지 않다.
음성: 새 작업 상태가 코드에 추가되고 사전에 없으면 테스트가 실패한다.

## REPORT-001-REQ-02 단일 원본과 연동 경계

공통 지침(AGENTS.md)은 이 규칙을 짧게 가리키기만 하고 표를 복제하지 않는다. 별도 변환 엔진·DB·서비스·LLM 호출 경로를 만들지 않는다.
향후 브리핑 스킬은 이 표를 결정론적 매핑으로 공통 출력 계층에 사용한다.

### REPORT-001-AC-02

AGENTS.md는 `docs/reporting.md`를 참조하고, AGENTS.md·CLAUDE.md·docs/sdd.md에는 사전의 표 행(예: `| V1 |`)이나 표시 명칭 정의가 없다.
`src/` 아래 코드는 이 문서를 읽지 않는다(변환 엔진 없음). 음성: 공통 지침에 표 행을 복제하면 테스트가 실패한다.
